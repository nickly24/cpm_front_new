# Домашние работы: интерфейс и целостность процесса

Изменения 12 сентября 2026 года. Реализация предназначена для совместного выпуска frontend, основного backend и homework service.

## Для ученика

- Список различает подготовку, черновик, отправку, проверку, доработку и результат. Поиск, фильтры статуса и типа доступны на телефоне.
- Работа открывается по ссылке `?work=<homework_id>`; браузерная навигация и переход из центра загрузок работают из любого раздела.
- Один рабочий экран на телефоне, основное действие в нижней панели. PDF просматривается постранично, с масштабом и скачиванием.
- Прикрепление создаёт черновик, отдельная отправка передаёт PDF проверяющему. Доступны замена и подтверждаемое удаление черновика.
- Ошибки файла и передачи видны; повтор использует исходный File, а не локальный идентификатор как серверный. Серверные загрузки продолжают отслеживаться после перезагрузки.
- Перезагрузка не сохраняет ещё не переданный File: студент может дождаться загрузки из другой вкладки либо отменить её и выбрать файл снова.

## Сканер

Один активный экран: страницы, обработка, разметка или камера. Крупные элементы управления, горизонтальная лента страниц, закреплённая подготовка PDF. Обрезка применяется явно; предпросмотр и экспорт используют общий рендеринг фильтров и поворота. В текущем сеансе доступна отмена последней правки.

Новые локальные проекты привязаны к аккаунту. Старые записи без владельца не переносятся автоматически между аккаунтами и остаются в прежнем локальном хранилище до очистки при выходе. PDF и разметка остаются изображениями, отдельные слои разметки не хранятся.

## Для проктора и администратора

- Очередь: поиск, фильтры, продолжение списка, ответственный, сведения о файле. Работа другого проверяющего не показывает недоступные действия.
- Рабочее место проверки: PDF и форма рядом на компьютере, отдельные вкладки на телефоне. Оценка — целое число 0–100; автоматический расчёт включается явно и показывает будущий балл.
- Доработка требует комментария; ошибки и успешные действия видны в интерфейсе.
- Проктору доступен архив учеников его текущей группы, повторный просмотр PDF, изменение оценки и открытие пересдачи. Удаление результата требует подтверждения.
- Права сотрудников учитываются при переходе из очереди в архив и обратно: успешное действие не превращается в ошибку из-за отсутствия доступа к следующему разделу.
- В старом журнале файловая работа открывает рабочее место проверки. Старые ручные операции не меняют её статус и оценку. Массовое занесение пропускает файловые работы.

## Backend

Основной backend проверяет текущую группу проктора при чтении и изменении домашних работ. Файловые сдачи защищены от параллельного изменения старым API; списки возвращают актуальные файловые статусы.

Homework service поддерживает пагинацию/поиск очереди и архива, метаданные файлов, предложенную оценку, удаление черновика. Исправлены повторный submit, валидация оценки, конкурирующие загрузки, retry/cancel, истечение прерванной передачи, блокировки MySQL и завершение worker.

Дополнительная миграция не нужна: используется существующая `001_homework_files.sql`. Основной backend сохраняет прежнее поведение без файловых таблиц. Новая опциональная настройка `UPLOAD_STALE_SECONDS` по умолчанию — 1800 секунд.

История версий не добавлена: сохраняются текущий файл и черновик; при замене старые объекты удаляются по существующей схеме. Повторная отправка по-прежнему обновляет дату сдачи. Эти правила не менялись.

## Сборка и проверка

PDF.js уже был зависимостью проекта. `predev` и `prebuild` копируют worker из установленной версии `pdfjs-dist` в `public/pdf.worker.min.mjs`; сгенерированный файл исключён из Git и ESLint. Это предотвращает несовпадение версии просмотрщика и worker после установки зависимостей.

Локальные браузерные проверки используют только синтетические аккаунты, PDF и подменённые API. Запросы к настоящему backend/S3 блокируются:

- `node scripts/homework-student-ui-smoke.mjs`
- `node scripts/homework-staff-ui-smoke.mjs`
- `node scripts/homework-scanner-ui-smoke.mjs`

Для них dev frontend запускается на `http://localhost:3010`, обе переменные `NEXT_PUBLIC_API_BASE_URL` и `NEXT_PUBLIC_HOMEWORK_SERVICE_URL` — `http://127.0.0.1:5099`. Playwright задаётся через `PLAYWRIGHT_MODULE`; используется установленный Chrome. Итоги и скриншоты сохраняются в `outputs/homework-redesign` родительского workspace либо пути `SMOKE_OUTPUT`.

Проверки backend выполняются изолированно, без MySQL и S3. Перед выпуском на сервере нужен стандартный smoke с реальными настройками авторизации, S3/CORS и применённой существующей схемой. В рамках этой доработки production не изменялся.
